## Context

现有 staged 策略检索会先请求一个结构化题面描述，再由 `strategy_retrieval.py` 中的 `StrategyRetriever` 加载 `Qwen3-Embedding-0.6B`，将原题和结构化描述编码为 1024 维向量，并以 `0.2` 与 `0.8` 混合余弦分数。该模块在导入时依赖 PyTorch 和 SentenceTransformer，运行时需要完整模型权重。详见 [proposal.md](proposal.md) 与新增词法检索规格。

策略卡已有稳定的 JSON 元数据和卡片渲染链路，staged runtime 已将原题、结构化描述、分类结果和 Top-K 卡片分开保存，因此可替换候选排序实现而不改变 Solver 注入格式或平台接口。

## Goals / Non-Goals

**Goals:**

- 让默认策略检索在无嵌入模型、无 GPU 和无网络的环境中完成。
- 从固定策略卡语料预先构建可验证、可重复加载的 BM25 与 TF-IDF 索引。
- 以结构化初始策略描述为主、原题为辅，按固定比例融合两类词法分数和有限元数据匹配信号；题面约束校验始终优先于结构化描述。
- 保持现有策略卡 ID、卡片渲染、trace 结构及 `ReasoningAgent.solve` 合约稳定。
- 保留已有嵌入模型和向量索引，以便后续显式选择语义检索或进行对照。

**Non-Goals:**

- 本变更不删除、不迁移或重建 `Qwen3-Embedding-0.6B` 及其 `strategy_embeddings.npy`。
- 本变更不将 BM25/TF-IDF 解释为跨语言语义模型，也不承诺将英文术语自动翻译为中文同义概念。
- 本变更不修改远程 client、Solver、审查、策略卡正文或官方平台接口。
- 本变更不以特定题目、题目编号或已知答案优化词表、别名或排序规则。

## Decisions

### 1. 词法默认检索与嵌入检索解耦

新增独立的词法索引与检索模块，默认 staged runtime 仅导入该模块。原嵌入检索模块、权重准备函数和向量数据原样保留，不再作为默认调用链的一部分。

原因：仅在运行时“不调用”嵌入编码仍会因模块顶层导入 PyTorch/SentenceTransformer 而形成环境依赖。独立模块使无嵌入依赖成为可验证的默认行为。

备选方案：在现有 `StrategyRetriever` 中增加模式分支。未采用，因为该模块的导入依赖仍存在，且词法索引的生命周期、完整性校验与测试边界会与模型加载逻辑混杂。

### 2. 一个离线构建器，多个受版本约束的轻量产物

新增可重复执行的构建命令，从策略卡源数据生成：

- 词表及规范化配置；
- 策略卡文档频率、词频、文档长度、平均长度和倒排 postings，供 BM25 查询；
- 策略卡的 L2 归一化稀疏 TF-IDF 表示，或能等价计算其余弦分数的紧凑表示；
- 包含源卡片规范化摘要、卡片 ID/顺序摘要、词法规则版本、维度与构建参数的 manifest。

索引优先使用 JSON、NumPy 和标准库可加载的数据格式；若稀疏存储需要额外格式，应由构建器和运行时共同实现，避免新增运行时检索服务或重量级框架。写入采用临时文件加原子替换，避免并发构建留下半成品。

原因：策略卡固定而查询动态，预计算策略侧统计可消除逐题扫描语料的成本；manifest 阻止卡片与索引错位。

备选方案：每道题临时拟合 TF-IDF/BM25。未采用，因为会重复扫描语料、产生不可控延迟，且无法稳定审计版本一致性。

### 3. 英文 token 优先、中文字符 n-gram 补充的统一规范化

规范化器对策略卡与查询共用，输出 token 计数。英文单词、数字及常见数学符号序列经 Unicode/大小写规范化后保留；连续中文文本生成长度 2 到 4 的字符 n-gram。LaTex 控制词、下标和连接符按稳定规则保留为可检索 token；单字符高频噪声、纯标点和空 token 被丢弃。

可维护的通用数学术语规范化表仅限通用别名，例如 `DP` 与 `dynamic programming`、`Hamiltonian` 与其大小写变体；表的来源和版本写入 manifest。不得加入题目编号、答案或单题特化规则。

原因：策略卡主要英文，英文词界对 BM25 有效；少量中文不适合强制依赖中文分词库，字符 n-gram 对短术语和混合文本更稳。

备选方案：引入中文分词服务或只按空白切词。前者增加依赖且对英文数学公式收益有限，后者会丢失中文召回。

### 4. 结构化描述主导、题面约束优先的双查询融合

对每张卡分别计算原题 `P` 与结构化描述 `S` 的检索分数：

```text
lexical(Q, C) = 0.5 * normalized_bm25(Q, C)
              + 0.5 * normalized_tfidf_cosine(Q, C)

final(C) = 0.4 * lexical(P, C)
         + 0.6 * lexical(S, C)
         + bounded_metadata_bonus(C)
```

其中每类查询的 BM25 和 TF-IDF 分数在同一候选集内以确定性方式归一化，并按 `0.5/0.5` 固定融合；原题与结构化描述按 `0.4/0.6` 固定融合。实现阶段覆盖无 `S`、空候选和分数并列情况。领域、题型、义务只做有上界的加分或软过滤；任何与题面明示方向、范围、对象或端点约束冲突的结构化描述及其引导的候选均不得因该描述获得加分或优先级。

结构化描述来自现有结构化检索分析调用；它不是可信事实来源。其作为 0.6 权重的扩展查询时，运行时必须先以题面可验证的方向、范围、对象和端点约束检查冲突；若冲突，不允许该描述提高冲突候选的排序。若该调用失败，直接使用 `P`。

原因：结构化描述可较完整地概括领域和结构术语，因而作为主要检索信号；原题提供不可违反的硬约束，冲突校验确保生成描述不能覆盖题面。

备选方案：只检索原题，或按现有 `0.2/0.8` 偏重结构化文本。前者丢失结构摘要收益，后者会过度放大生成描述的错误锚点；采用 `0.4/0.6`，并以题面冲突校验作为安全边界。

### 5. 兼容、配置与故障行为

将默认检索模式设为 lexical，并提供显式配置值以选择 legacy embedding 或禁用检索。模式选择发生在 runtime 的检索入口，trace 将记录使用的模式、索引版本、候选卡 ID 与降级原因，但不记录完整题面、完整 prompt 或大块原始响应。

词法索引缺失、manifest 不匹配、损坏或查询异常时，保持现有“策略检索可选”的语义：记录降级并继续后续 Solver。不得在词法失败时隐式加载嵌入模型，因为这会重新引入设备与模型可用性风险；嵌入路径只能由显式配置启用。

## Risks / Trade-offs

- [词法检索无法理解跨语言同义改写] → 以英文术语、通用别名、中文 n-gram 和原题/结构双查询提高召回；保留嵌入实现供后续对照。
- [BM25 与 TF-IDF 原始量纲不同] → 在每次查询的候选范围内采用确定性归一化，并为零方差、无命中和并列定义稳定规则。
- [索引和卡片元数据错位] → manifest 绑定源语料摘要、卡片 ID 顺序和规范化规则，运行时拒绝不匹配索引。
- [倒排索引 JSON 体积或加载时间增长] → 策略库规模有限；构建时统计产物大小，并在测试中覆盖加载与 Top-K 延迟预算。
- [结构化描述误导检索] → 结构化描述虽以 0.6 权重参与融合，但先接受题面约束冲突检查；冲突描述不得提高冲突候选的排序，原题仍以 0.4 权重保留直接词法信号。

## Migration Plan

1. 在不改动现有嵌入资产的前提下，加入词法构建器和生成的索引产物。
2. 加入词法检索器、完整性校验和单元测试，使用固定策略卡 fixture 验证确定性排名。
3. 将 staged 默认入口切换到 lexical，并保留显式 legacy embedding 配置。
4. 使用本地 JSONL 做无嵌入模型冒烟测试，确认 trace、策略卡注入和最终响应合约不变。
5. 若词法索引出现不可接受的召回或运行问题，可将配置切回 legacy embedding；不删除任何词法或嵌入资产。
