## Purpose

该能力用于把 `custom2` 的推理 Runtime 改造成三层状态机，使证据、完成条件和任务调度彼此解耦。这样系统在复杂题中可以动态换路线、独立判断是否可以收敛，并避免单个任务状态错误拖死最终输出。

## ADDED Requirements

### Requirement: 证据层必须只接受已验证事实
系统 MUST 将已通过验证的数学事实作为权威状态保存；未验证的候选内容不得进入权威证据层。权威证据至少包含题目事实、定义、推导结果和候选答案。

#### Scenario: 未验证内容不能写入权威状态
- **WHEN** solver 提交新的推导或候选答案但尚未通过验证
- **THEN** 系统 MUST 仅将其视为候选提案，不能当作权威证据供后续步骤直接引用

#### Scenario: 验证通过后成为可引用证据
- **WHEN** verifier 接受某个新事实、定义、推导结果或候选答案
- **THEN** 系统 MUST 将其写入权威证据层，并允许后续步骤引用

### Requirement: 完成条件必须独立于任务状态判断
系统 MUST 使用独立的完成条件集合判断是否可以收敛到最终答案；系统不得仅依据任务是否全部结束来决定能否 final。不同题型可以对应不同完成条件，但 final gate 的判定逻辑必须独立于任务队列状态。

#### Scenario: 任务未清空但完成条件已满足
- **WHEN** 关键完成条件已经全部满足，但仍存在不影响答案的开放任务
- **THEN** 系统 MUST 允许进入最终整理流程，而不是因为任务未清空而阻止 final

#### Scenario: 任务已结束但完成条件未满足
- **WHEN** 所有任务都已标记完成，但关键完成条件仍未满足
- **THEN** 系统 MUST 拒绝进入 final，并继续要求补足缺失条件

### Requirement: 任务层必须支持动态重规划
系统 MUST 将下一步工作建模为动态任务队列。任务可以被创建、拆分、替换、失效化、阻塞或恢复；任务状态只表示局部推进情况，不得直接充当整题完成标准。

#### Scenario: 当前路线失效时替换任务
- **WHEN** 某个任务连续失败或被判定不再可行
- **THEN** 系统 MUST 允许失效该任务并生成新的任务集合，而不是强制继续同一路线

#### Scenario: 无可执行任务时自动补任务
- **WHEN** 当前没有可执行任务，但仍有未满足的完成条件
- **THEN** 系统 MUST 触发重规划并生成新任务，直到出现可执行路径或预算耗尽

### Requirement: 每次有效推进必须推进某个完成条件
系统 MUST 在每次接受一个局部步骤后检查其是否推进了至少一个完成条件。若步骤只是在重复已知内容、关闭了错误任务，或没有产生新的可验证推进，则系统 MUST 视为无效推进并触发修复或重规划。

#### Scenario: 仅复述已知内容不算推进
- **WHEN** solver 提交的步骤没有引入新的可验证证据，也没有改变任何完成条件状态
- **THEN** 系统 MUST 认为该步骤未推进，并应记录失败原因以便修复或重规划

#### Scenario: 新证据推进了完成条件
- **WHEN** 一个新结果或新候选答案被验证后确实满足了某个完成条件的部分或全部需求
- **THEN** 系统 MUST 更新对应完成条件状态，并继续围绕剩余未满足条件推进

### Requirement: 历史消息与状态注入必须分离
系统 MUST 将已通过验证的推理步骤保留为对话历史的一部分，同时 MUST 将运行状态、未满足完成条件、错误记忆和当前任务作为每轮提示词注入，而不是不断把相同状态重复追加进历史消息。运行状态可用于本轮推理，但不得伪装成新的对话轮次。

#### Scenario: 已验证步骤进入历史
- **WHEN** 某个局部步骤通过验证
- **THEN** 系统 MUST 将该步骤作为历史上下文保留，供后续轮次持续参考

#### Scenario: 运行状态作为临时注入
- **WHEN** 系统准备发起新一轮推理请求
- **THEN** 系统 MUST 单独注入当前状态摘要、未满足完成条件、错误记忆和活动任务，而不是把同一份状态反复追加成新的对话消息
