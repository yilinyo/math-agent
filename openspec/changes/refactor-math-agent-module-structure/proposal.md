## 为什么

当前数学推理 Web 应用的图状态、路由、checkpoint 校验和图执行集中在 `agent_platform/graph_runtime.py`，各阶段逻辑集中在 `staged_adapter.py` 的分支中，平台运行机制与推理业务交织，增加了定位和维护成本。需要按职责调整模块结构，使图编排和节点实现易于查阅，同时严格保持现有行为。

## 变更内容

- `agent_platform/` 聚焦 HTTP/SSE、任务调度、取消、超时、恢复、持久化和对外展示；整理为入口、服务、依赖装配、运行接口、存储与展示模块。
- `agent_platform/agent/` 承接当前 Web 应用的推理业务：将图构建、state 定义、条件路由、依赖接口和节点执行逻辑拆入 `graph.py`、`state.py`、`routing.py`、`dependencies.py`、`nodes/` 等对应模块；按实际依赖整理 prompts、schemas、retrieval 和 tools。仅移动或提取原实现，不重新设计其内容。`reasoning_agent/` 保留原有历史格式和实现，通过现有接口复用，不向其中新增本次 Web 编排模块。
- 将现有各节点分支提取为独立执行入口，覆盖 profile、retrieve、plan、solve、tool、verify、repair、emergency、arbitrate 和 finalize；图文件清楚展示现有节点与边，注册方式调整必须保持原图语义和允许的转移集合。
- 整理本地与分布式启动的依赖装配到 `bootstrap.py`，保持启动参数、默认值、资源生命周期和可信客户端注入边界；模型客户端不得在推理节点或浏览器内构造。
- 按单元、集成和端到端职责整理测试，并增加确定性行为对照，验证拆分前后的模型请求、节点轨迹、状态更新、工具调用、事件和最终输出一致。
- 对受影响的既有导入入口提供必要兼容，并同步维护文档、测试发现和 CI 路径，避免目录调整破坏调用方。

### 行为不变约束

- 以当前 Web 入口使用的 `agent_platform/graph_runtime.py`、`staged_adapter.py` 及其实际依赖为基准；不直接切换到未跟踪的 `reasoning_agent/langgraph_final/`，不覆盖该目录及其他已有工作。
- 保持节点执行顺序、条件边判断、重试与恢复路径、模型和工具调用顺序、预算控制、超时收尾、候选选择、校验、审计、仲裁以及默认 3 轮 repair。
- 保持提示词全文、消息角色和拼装方式、上下文内容、结构化输出解析、模型请求参数与原有回退逻辑。
- 保持 state 的字段、类型、默认值、读写语义、序列化形式及 checkpoint 载荷、版本和校验规则；不得借拆分重命名、增删或重新设计状态。
- 保持 checkpoint 兼容性判断的实际效果；源码迁移涉及的哈希计算须在设计中明确处理并验证，不得绕过校验、无条件接受旧 checkpoint，或因搬迁使原可恢复任务无故失效。
- 保持 HTTP/SSE 合约、幂等性、并发与取消、历史隔离、工具执行记录、安全脱敏、答案渲染和错误语义。对照测试只规范化时间戳、随机标识等非确定值，不掩盖业务差异。
- 保留现有检索代码、策略语料和必要历史实现的运行依赖；保留本地状态、问题文件和聊天历史。

### 非目标

- 不优化或重新设计解题流程、提示词、state、检索算法、评分机制或模型配置。
- 不收紧或扩展原有图边，不引入新 Agent 工作流，不重新实现已有推理算法。
- 不新增产品功能、外部依赖或数据库迁移，不恢复已移除的竞赛入口、JSONL runner 或离线评测工具。
- 不修改前端交互，不清理数据与历史产物，不提交或推送代码。

## 能力

### 新增能力

无。本次为保持行为等价的内部结构重构。

### 修改能力

无。既有功能要求和外部行为保持不变。变更元数据设置 `skip_specs: true`，不创建行为规格增量。

## 影响

- 代码范围：`agent_platform/`、相关测试、启动与 CI 脚本及当前应用文档。`reasoning_agent/` 的实际依赖仅调查和复用，保持原有结构与内容；`client/` 仅执行既有回归检查；`judge/` 和无关工作区文件不属于本次范围。
- 主要风险：模块搬迁导致循环导入、旧导入失效、源码哈希变化、资源初始化顺序变化，以及提取节点时状态更新或异常处理发生偏移；后续设计需逐项明确兼容方式。
- 验证范围：以固定模型响应验证正常解题、检索与工具调用、校验及修复循环、应急求解、仲裁、预算耗尽、异常收尾、取消和 checkpoint 恢复；保留平台 API/SSE、存储和隔离回归。无需真实模型调用。
- 完成标准：目标职责划分可直接从模块和图定义中理解，且重构前后可观察行为与状态契约一致；运行 Python 测试、前端测试与构建，并按项目 CI 要求报告结果及未覆盖的外部服务限制。
