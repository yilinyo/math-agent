## Why

当前 `custom2_staged` 通过画像、检索与策略规划后，主要依赖一次完整 Solver 输出；严格数学证明、四章节格式与多轮验证同时挤入长响应，容易出现截断、探索噪声积累和错误前提复用。新增基于 LangGraph 的分阶段数学 Agent，用显式状态、分步执行、可追溯事实精炼和验证回退支持长程求解。

## What Changes

- 新增独立 `custom2_langgraph` 模式，对齐 `custom2_staged` 的题目画像、策略案例检索、技能材料及官方注入客户端；现有默认模式及检索实现保留。
- 使用双层 Plan-and-Solve：外层分析与规划、完整证明验证和修复；内层连续多步推导、按需 Python 与主动关键结论检查，不做逐步审查或事实 commit，不采用无全局计划的通用 ReAct 主循环。
- 每轮尽量生成多个完整数学步骤，按需调用工具并暂停，回填后续写未完内容及后续步骤；没有工具不代表结束，只有独立的非空 `### 最终答案` 段才正常退出推导、提取候选并进入整题验证。简单题允许一轮完成详细步骤与候选，长题允许多轮续写，截断时保留可安全解析正文。
- Solver 只有需要实际计算或主动检查关键结论时交出控制权，不设固定检查点或“无法继续”分支。每步严格保持指定五字段及连续编号，计算/检查报告另存；局部检查不替代最终审查。
- 保留原流程的结构化检索、案例置信度、技能与定理材料、保真审查及修复时材料刷新；取消新模式中未验证候选的成功出口。平台状态使用现有 `solve_status` 契约。
- 分离问题分析、详细步骤、关键验证点、最终答案四类生成职责；程序按用户要求的四章节顺序组装结果。
- 数学上下文保留原题约束、目标、完整有效草稿、公式条件、真实计算结果和未完尾部；不把未经整题验证的草稿压成已证引理，证明正文完整保存以支持外层审查和回滚。
- 内部 Solver 正常轮次追加 assistant/tool/user 消息并同步保存在 state；使用原生 tools/tool_calls 与匹配的 tool_call_id。临近预算或撤销/路线变化时从有效数学台账重建上下文，不每轮重新发送整份工作视图。
- 验证失败或自我否定证据触发依赖失效和回到推导；默认最多三轮修复，受总时限和循环预算约束。未验证候选不能升级为成功答案。
- 将用户指定的答案类型、选择题真值表、证明完整性、独立复算、边界覆盖和四章节格式落实为节点协议与验收标准。

## Capabilities

### New Capabilities

- `langgraph-staged-math-runtime`：独立模式、分阶段图执行、受控 Python 工具、检索复用、验证回退及运行预算。
- `mathematical-context-ledger`：事实来源、证明依赖、工作上下文精炼、失效传播和证明正文保留。
- `staged-math-answer-contract`：解题前检查、题型求解义务、实际验证证据及四章节最终输出。

### Modified Capabilities

无。现有模式保持兼容；本变更新增独立能力。

## Impact

- 计划新增 `reasoning_agent/langgraph_math/`，接入 `reasoning_agent/factory.py`，新增独立配置、测试和 README 使用说明。
- 工程划分为图装配、节点、路由、求解/验证子图、领域状态逻辑、客户端/检索适配及工具层；节点状态与运行依赖分离，具体契约和验收映射集中在 design.md。
- 新增 LangGraph 依赖，实施时验证 Python/Pydantic 兼容版本并限定范围；现有模式不应因可选模式导入而失败。
- 复用 `custom2/model_call.py`、策略检索与技能材料的可复用接口；不直接调用旧 runtime 的整题 `run`，不复制整套旧实现。
- 保持 `ReasoningAgent(client=...)` 与 `solve(problem, metadata)` 契约；模型请求只使用官方注入客户端。
- 不涉及 judge 仓库、数据集生成、索引重建、策略库生成、提交或上线；本次交付包括规划文档、独立模式实现和离线验收。
