## Purpose

维护数学求解的事实来源和证明依赖，将长程探索中的有效信息精炼成可控工作上下文，同时保留完整可读证明与真实工具证据，使错误发现后能够撤销关联结论而不污染后续推导。

## ADDED Requirements

### Requirement: 事实与假设严格分层
系统 MUST 区分题面事实、已证明引理、计算观测、待证义务、猜想及已失效结论。每项有效事实必须有稳定标识、来源、适用条件、依赖与版本。LLM 自称“已证”、策略案例和有限计算不得直接成为一般性已证事实。

保存步骤正文不等于接受其全部结论。当前分段模式 MUST 将生成步骤保存为 draft，不做单步事实晋升；工具成功仅产生给定输入与范围下的计算观测。完整证明及候选在外层统一审查，不能以草稿编号或存储行为声称已证。

#### Scenario: 局部检查记录不晋升事实
- **WHEN** Solver 主动检查的关键结论得到局部 pass
- **THEN** 记录命题、实际依据、范围及内部版本，后续上下文可读但不晋升为 lemma；正文修订或依赖失效后旧结果不能作为当前有效依据，整题仍须独立审查

#### Scenario: 计算观测不升级为定理
- **WHEN** Python 对有限 n 验证命题成立
- **THEN** 台账仅保存给定范围的观测，一般命题保持待证，直到相应证明义务被检查闭合

### Requirement: 同一步的暂停续写与上下文回填
系统 MUST 保存当前未完成尾部、程序内部稳定标识、生成轮次及关联工具请求。一轮可完成多步，数学步骤与请求轮次独立计数。每轮续写上下文必须包含原题与约束、全局路线、全部义务、完整有效草稿、实际观测及其条件、pending 和本轮协议；不得让模型回传内部版本或步骤ID。待完成内容不得混入已验证事实；工具结果本身不新增数学步骤。

#### Scenario: 同一步多次请求工具
- **WHEN** 当前步骤需要先计算初值再检查递推，两次工具请求均属于该步骤
- **THEN** 系统记录不同请求及生成轮次，保留真实结果和未完尾部，续写完成后正文只保存一次，并允许继续生成多个步骤

#### Scenario: 失败后重新生成
- **WHEN** 工具返回错误或超时
- **THEN** 下轮接收真实失败状态及必要输入，在预算内修正计算或改用有效推导，不能将预期值作为已获得的结果

### Requirement: 精炼保留核心约束
系统 MUST 在组装工作上下文时保留原始题面、输入、目标、公式及条件、完整有效草稿、Python 实际值与范围、全部义务、未完尾部、当前路线和关键失败禁用原因。可整体省略可选参考噪声，不得为压缩把草稿提升为确定事实，也不得改写方向、量词、定义域和端点。

#### Scenario: 连续消息和数学台账同时保存
- **WHEN** Solver 正常连续生成多轮
- **THEN** state 同步保存 solver_messages 中的 assistant/tool/user 历史与独立的步骤/证据/未完尾部，正常轮次追加而非全量重建；父子图输出和异常快照保留这些内部状态，不向平台诊断泄露完整消息

#### Scenario: 预算临界或撤销时重建消息
- **WHEN** 消息和工具定义达到工作窗口预算85%，或关键结论失败、版本/路线/材料等核心上下文发生变化
- **THEN** 从有效数学 state 重建完整 system 与十区块 user，舍弃旧会话噪声与已撤销错误的 assistant 历史，保留完整数学核心、真实计算和检查反馈；重建后仍超硬预算则诚实退出

#### Scenario: 精炼处理调试噪声
- **WHEN** 历史包含失败代码、冗长报错与一个有效计算结果
- **THEN** 后续求解上下文移除冗长噪声，保留有效结果及来源和必要失败原因，且所有原题约束仍可恢复核对

#### Scenario: 核心信息超预算
- **WHEN** 不可省略的约束与必要证明依赖仍超过上下文预算
- **THEN** 系统按当前义务选择依赖闭包或明确结束为未完成，不截断原题条件或伪造压缩事实

### Requirement: 依赖失效传播
系统 MUST 在事实被反驳或模型修订时撤销所有受影响的下游引理、步骤、计算适用性、候选与验证票据，并保留独立有效事实。旧版本证明不得混入新版本最终输出。

若依赖关系不完整而无法可靠确定影响范围，系统 MUST 保守失效从错误步骤起的后续相关推导，不能因模型未声明依赖而继续使用可能受污染的结论。

#### Scenario: 上游引理被反例否定
- **WHEN** 引理 A 被反驳且结论 B 和答案 C 依赖 A
- **THEN** A、B、C 失效，独立结论 D 保留；后续上下文与最终答案不能使用 A、B、C

#### Scenario: 依赖声明缺失
- **WHEN** 一个后续结论可能使用已反驳步骤，但没有可靠的独立性证据
- **THEN** 系统保守撤销该结论并要求重新建立依据，而非认定无依赖

### Requirement: 工作记忆与证明正文分离
系统 MUST 保留有效步骤的完整可见证明和计算依据，精炼只缩小后续模型工作上下文。验证必须能读取所审计依赖对应的完整证明，不能仅凭摘要验证；最终四章节必须能独立判分。

#### Scenario: 长证明经过多次精炼
- **WHEN** 求解完成前工作上下文多次压缩
- **THEN** 最终详细解题步骤仍包含必要完整证明链，审计可定位原始有效步骤而无需依赖隐藏状态

#### Scenario: 子流程预算结束
- **WHEN** 推导子流程在完成数步后耗尽预算
- **THEN** 已提交步骤和证据仍可用于诚实的未完成报告，未完成步骤不自动晋升或覆盖有效档案
