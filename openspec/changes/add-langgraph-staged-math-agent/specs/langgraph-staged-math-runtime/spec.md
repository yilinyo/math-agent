## Purpose

提供可单独选择的分阶段数学求解流程，复用现有策略检索与平台客户端，通过有预算的逐步推导、实际计算和验证回退，使长题求解过程可追踪，并避免未验证结果被包装为成功答案。

## ADDED Requirements

### Requirement: 独立模式与平台兼容
系统 MUST 支持 `custom2_langgraph` 模式，保留现有模式与默认选择，接受注入客户端及可空 metadata，返回含非空 `final_response` 的 JSON 可序列化字典。所有模型调用 MUST 使用注入客户端，不依赖本地密钥、参考答案或 metadata.idx。输出 MUST 使用现有 `solve_status=success|timeout|failed` 契约；内部未完成及运行错误映射为 failed，超时映射为 timeout，并保留具体原因。

#### Scenario: 平台初始化及模式隔离
- **WHEN** 平台使用注入客户端选择新模式并以 metadata=None 求解
- **THEN** 系统正常执行独立流程，输出契约合法；旧模式不受新模式的可选依赖加载影响

### Requirement: 分阶段规划执行
系统 MUST 分别生成分析、分段推导、验证及最终答案；不得要求单次输出完整四章节。每轮推导 MUST 在预算内尽量推进多个完整数学步骤，不设置一轮一步限制；简单题可以一轮完成详细步骤和候选。每一步仍 MUST 包含用户规定的完整数学字段，不以省略证明减少调用。生成轮次和数学步骤数 MUST 分开记录。

#### Scenario: 单轮多步完成
- **WHEN** 一轮响应生成六个完整步骤及非空最终答案段
- **THEN** 系统分别保存六步并提取候选，不拆成六次模型请求，也不执行单步模型审查

#### Scenario: 分段续写
- **WHEN** 一轮生成多个步骤但没有最终答案段
- **THEN** 系统保留已生成步骤、原题、路线和实际工具结果，在下一轮继续后续步骤，不重新生成全部正文

#### Scenario: 响应截断
- **WHEN** 生成响应被输出长度截断且 content 前缀可安全解析
- **THEN** 系统保留完整步骤、将未完尾部加入 pending，继续续写；不执行截断工具或采纳截断答案，无法解析时仅做有界协议恢复

### Requirement: 分段推导与最终答案标记
Solve 子图 MUST 默认连续多步生成，仅在主动提交计算或关键结论检查请求时暂停；MUST NOT 执行逐步 step_review、commit、finish_gate 或新增“无法继续”分支。普通响应使用 content JSON；计算/检查 MUST 通过原生 tools/tool_calls 请求，适配器转换为内部 tool/check，同轮两个请求互斥；内部版本和步骤ID由程序管理。没有请求不代表完成；只有代码块外独立的 `### 最终答案` 标题及非空答案段才能正常结束推导并进入整题验证，预算和异常另设非成功出口。候选存在不代表验证通过。

#### Scenario: 原生工具消息配对
- **WHEN** Solver 发起一个原生 python_executor 或 check_conclusion 调用
- **THEN** 校验唯一非空ID、函数名和完整参数；执行后保存匹配 tool_call_id 的真实 tool 消息，后续追加 user 要求，不将 JSON 控制字段或截断调用伪装成原生工具调用

#### Scenario: 主动关键结论检查
- **WHEN** Solver 完成多个步骤并提交正文中的精确 claim 和送检 reason
- **THEN** 系统只检查该命题及必要依据，回填实际判定后继续同一个多步生成循环；普通公式不增加模型检查，局部通过不省略整题审查

#### Scenario: 请求互斥和截断
- **WHEN** 同轮同时请求 tool 和 check，或响应被截断
- **THEN** 冲突请求不执行并在协议预算内恢复，截断仅保存可解析正文而不执行计算/检查或采纳候选

#### Scenario: 有限反馈后继续
- **WHEN** 关键检查返回不确定或有具体证据的失败
- **THEN** 不确定只反馈补证；有证据失败撤销对应正文及受影响后段，Solver 自行修正继续，不新增内层重规划或“无法继续”路径

#### Scenario: 重复请求或预算耗尽
- **WHEN** Solver 对相同上下文反复请求同一检查，或连续没有新内容
- **THEN** 重用已有结果并计入无进展预算；耗尽后以非成功结果结束，不无限循环或反复调用检查模型

#### Scenario: 多步后请求工具
- **WHEN** 本轮完成步骤1至3并在步骤4中请求 Python
- **THEN** 完整步骤立即保存，未完成尾部保留；真实结果回填后补齐步骤4并允许继续多个后续步骤

#### Scenario: 工具与结束标记冲突
- **WHEN** 同轮包含工具请求和最终答案段
- **THEN** 优先交出工具控制权，不采纳过早候选；工具运行后继续生成，不执行尚未完整返回的请求

#### Scenario: 无效结束信号
- **WHEN** 只有普通提及、代码块/引用中的标题、空最终答案标题或孤立 boxed
- **THEN** 不因此退出推导或伪造候选，继续生成并受全局预算约束

### Requirement: 策略参考沿用
系统 MUST 复用现有词法、向量、加权混合及 RRF 检索可配置能力和领域技能材料，不删除现有实现。加权混合使用词法 0.3、向量 0.7。适用策略优先落实为当前题步骤和验证义务；弃用须记录对象、约束、方向或前提冲突。不得复制案例答案、数值或题目作为本题事实。

检索适配 MUST 区分召回通道、分数加权融合与 RRF、融合参数、候选数及最终注入数，不能将已有 hybrid 名称等同于全部算法。保留结构化检索文本、案例置信度及规划/推导材料区分；修复时根据具体审计证据刷新相关技能材料并保留跨轮错误禁用原因。

#### Scenario: 检索案例与题面方向冲突
- **WHEN** 案例使用无向关系而原题指定有向关系
- **THEN** 系统保留原题方向、记录冲突并弃用冲突部分，其他适用材料仍可参考

#### Scenario: 检索资源不可用
- **WHEN** 本地检索不可用或无结果
- **THEN** 系统记录降级原因并从原题继续分析，不能伪造策略来源

#### Scenario: 关闭额外策略模型
- **WHEN** 额外策略模型调用被配置为关闭
- **THEN** 系统仍从分析结果和适用材料形成显式路线及证明义务，不退化为无全局目标的工具循环

#### Scenario: 定向修复刷新材料
- **WHEN** 验证否定当前递推或建模方式
- **THEN** 系统利用失败对象、证据和替代路线刷新技能材料，同时保留原题约束与被否定路线的禁用原因

### Requirement: Python 真实计算与资源约束
系统 MUST 允许受控数学 Python 计算与枚举，并记录执行标识、输入或状态、范围、输出和执行状态。工具 MUST 限制执行时间、输出、内存及可访问能力；不得访问网络、密钥、项目文件或启动任意命令。执行失败、超时、未运行或截断输出不得作为验证成功证据；有限枚举不得自动提升为一般证明。

#### Scenario: 枚举完成和失败区分
- **WHEN** 一个计算正常结束，而另一个枚举超时
- **THEN** 前者仅支持其实际覆盖范围内的结论；后者记录未完成并阻止“枚举确认”的断言

### Requirement: 验证回退与终止
系统 MUST 将验证结果区分为通过、失败、不确定；仅通过可进入最终答案生成。自我否定证据 MUST 使受影响候选及其依赖失效，回到推导重建；核心模型或必要条件冲突时必须切换方法。默认修复轮次为三轮，另设步骤、工具、无进展和总时限预算，单题不超过平台二十分钟并预留返回时间。

系统 MUST 保留程序/协议检查、题面保真检查和数学完整性审计的不同职责。不确定必须阻止定案并请求补证，不能仅因“不确定”就声称原结论已被反驳。旧候选只能在当前版本及验证仍有效时用于最终输出。调用超时但底层请求是否结束无法确认时，不得叠加新的恢复请求。

#### Scenario: 构造含重复对象
- **WHEN** 验证发现构造存在不允许的重复顶点
- **THEN** 系统不称验证通过，撤销依赖该构造的结论并回到推导

#### Scenario: 修复或时间预算耗尽
- **WHEN** 三轮修复后仍有未闭合问题，或剩余时间不足
- **THEN** 系统终止循环，返回四章节形式的明确未完成结果和非成功状态，不把已有猜测框为答案

#### Scenario: 审计不确定
- **WHEN** 审计缺少足够证据，但没有找到具体反例
- **THEN** 系统请求补充推导或独立检查，不将未确认命题标记为已证或已反驳

#### Scenario: 超时调用仍可能运行
- **WHEN** 调用等待超时且注入客户端未确认底层请求结束
- **THEN** 系统不再启动同题新请求，保存已提交进展并返回 timeout，不宣称成功取消请求

### Requirement: 诊断可审计且不泄露
系统 MUST 返回精简、JSON 安全的 trace，包含阶段、版本、预算、验证结论、失效原因和计算证据摘要；可选 debug_trace 不得泄露完整 prompt、原始模型响应、密钥、本地绝对路径或参考答案。

#### Scenario: 连续求解隔离
- **WHEN** 同一实例连续处理两个问题
- **THEN** 后一题不继承前一题的事实、Python 状态或验证结果，返回诊断不含禁止内容
