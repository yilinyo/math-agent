## Purpose

将用户要求的数学语义检查、完整求解纪律、独立验证及四章节输出定义为统一作答契约，使分阶段生成的分析、证明、选项判断和最终答案始终一致，并能作为完整结果独立判分。

## ADDED Requirements

### Requirement: staged 数学规则完整继承
系统 MUST 按节点职责保留 staged 原文中的答案语义、解题前检查、完整求解、验证纪律、策略参考及审计证据规则，不得以概括性短提示词替代原规则。整题一次输出、最多四步、旧 check 工具格式及旧 schema 等与新协议冲突的要求必须明确适配。领域角色和当前题触发的专项要求须传入实际求解、修复和审查请求；规划须能看到技能参考及目录，审计须看到无例题策略摘要及相关技能小结。

#### Scenario: Solver 按职责分层消息
- **WHEN** generate_step 首次发送或从有效 state 重建工作视图
- **THEN** system 包含领域角色、领域/专项/修复指导、完整求解纪律、步骤格式、工具/检查协议及响应 schema；user 不得直接使用整份工作字典的 JSON，必须按【原题】【题面约束】【当前解题路线】【技能参考】【策略案例（仅方法参考）】【已有推导】【待续写内容】【真实计算结果】【关键结论检查反馈】【本轮要求】依次渲染，空数据明确标注，不丢弃完整正文或失败证据

#### Scenario: 正常轮次增量续写
- **WHEN** 内部连续生成循环无需重建上下文
- **THEN** 保留完整 system 和首轮输入，按顺序追加已校验 assistant 回答、匹配ID的真实 tool 结果（若有）和新 user 要求，步骤格式与全部数学纪律持续有效，不每轮重复发送十个完整区块

#### Scenario: 每次生成仍保持原数学约束
- **WHEN** 同一步经过工具暂停、上下文精炼或外层修复后再次生成
- **THEN** 请求仍包含对应的 staged 原文数学规则、当前领域角色和专项要求，先续写未完内容，再允许连续生成多个完整步骤

#### Scenario: 直接审阅完整节点提示词
- **WHEN** 开发者打开任一节点提示词文件
- **THEN** 文件中直接可读完整的节点职责、适用数学规则、输入/字段含义、输出和失败处理要求；不得使用简短说明加运行时导入规则拼接代替完整正文，真实请求使用该完整正文

#### Scenario: 审计否定不在正文中的命题
- **WHEN** 审计给出的被否定命题不是所引用有效步骤的逐字原文，或缺少证据、影响范围和可执行修改
- **THEN** 系统将该意见降为不确定，只请求补证，不基于它撤销事实或指定未经验证的替代答案

### Requirement: 解题前语义检查
系统 MUST 明确答案类型为数值、表达式、集合、全部解、证明、构造或最值，并逐项核对定义域、量词、端点、互异性、有序性、重复性、方向、维数和运算结构。图模型须保持有向或无向、环面或边界与端点条件；例如相邻有序差不得擅自反向。类型、维数或定义冲突必须先说明字面结论，其他解释单列，不能悄悄修题。

#### Scenario: 不对称相邻关系
- **WHEN** 原题要求 x_i-x_(i+1) 属于 A 且未声明对称
- **THEN** 分析、建模及验证均保留该方向，不使用逆关系替代

### Requirement: 选择题与教材填空语义
系统 MUST 识别“选择一个/最佳/最适合”与“哪些/所有正确项/可多选”。未明说时不得默认单选；所有选择题必须建立含逐项理由的选项真值表，最终选项与按题干判定为正确的集合完全一致。对于最佳项题，判定对象是“是否满足题干的最佳要求”，不能仅因更宽语境可用而选中。教材标准或通常方法的单空题必须给完整首选术语，不因其他方法存在选择“以上都可以”。

#### Scenario: 未指明单选且两项成立
- **WHEN** 真值表证明 C、E 成立而其余不成立
- **THEN** 最终答案为 `$\boxed{CE}$`，不得漏项、增加选项、插逗号或改写为含糊描述

#### Scenario: 教材标准方法单空
- **WHEN** 题干只有一个空且要求通常采用的方法
- **THEN** 系统判断教材首选方法并输出完整术语，例如不能将“时间序列分解法”缩写为“分解法”

### Requirement: 完整求解义务
系统 MUST 先建立等价模型再选择主路线，每个关键结论说明公式、适用条件和实际代入，不以“显然”“标准结论”“容易看出”替代证明。最值须闭合界与合法取等；所有解及分类须证明必要、充分、完备；计数须说明有序性、重复规则和无重复计数；构造须可执行并逐条核验，不可能性须给充分矛盾。主路线遇到反例或必要条件冲突必须删去受影响候选并换方法。

#### Scenario: 只有下界
- **WHEN** 最小值推导仅得到下界而无合法取等构造
- **THEN** 义务保持未完成，不将下界作为最终最小值

### Requirement: 专项结构与几何复核
系统 MUST 按题型检查覆盖、铺砌、图论的局部到全局，最值的优化方向，函数与递推的端点和量词，概率统计的样本空间，代数结构的内部运算及所有边界分支。几何长度或比值题必须固定坐标或三角口径，给所求量独立表达式，并用第二角关系、正弦定理、坐标代入或极端构型复核。

#### Scenario: 几何图形直觉不足
- **WHEN** 推导仅凭图形声称两个长度相等
- **THEN** 验证不通过，要求独立表达式及额外关系复算

### Requirement: 实际验证证据覆盖
系统 MUST 至少给两个带实际对象和结果的验证点，并覆盖最小合法规模、边界情形、关键结构的非平凡案例；同一检查可覆盖多个义务。无某类可实例化对象时须说明不适用依据并给对应符号或退化检查，不编造规模。数值或闭式答案须用第二种表示、独立递推/枚举或代回约束复算，不一致不得定案。唯一性、全称或排他结论须主动尝试反例；最简答案须约分、消元、修正端点并转换类型。

按题型 MUST 覆盖：计数/递推的小规模枚举或初值及总数/重复检查；数论/函数的原式代回、模/整除及边界；几何的坐标或正余弦复算及第二角或尺度不变量；图论/铺砌/博弈的不变量、度数或奇偶及构造或反例；代数/分析的定义域、极端/退化及独立恒等变形。

#### Scenario: 闭式结果独立复算矛盾
- **WHEN** 闭式代入与独立递推给出不同结果
- **THEN** 系统回退重建，不选择任一结果作为已验证答案

### Requirement: 验证一致性硬门槛
系统 MUST 将重复对象、遗漏、非法边或操作、端点不符、计数矛盾、无解、需修正或“实际应为”等具体自我否定证据判为未解决缺陷，禁止据此声称通过。未执行枚举不得写“枚举确认”；声称执行须有范围、状态/输入和实际输出。已经解决的历史缺陷必须有新版本证据，不能简单凭否定词判错或凭模型自评判对。

#### Scenario: 自评通过但证据否定
- **WHEN** 验证文本声称通过，同时指出当前构造存在非法边
- **THEN** 以具体矛盾为准判失败，撤销依赖并重新推导

### Requirement: 四章节与逐步字段
系统 MUST 仅输出以下四个二级 Markdown 章节且顺序固定：`## 问题分析`、`## 详细解题步骤`、`## 最终答案`、`## 关键验证点`。分析含题型、答案类型、关键条件、方法、实际定理及前提和歧义口径。每步严格使用 `步骤 n｜目标：…｜使用公式/定理：…（含适用前提）｜代入题面：…｜推导/计算：…｜得到：…`；采用这一最终指定的完整字段版本。验证点 1 写实际代回、计算、枚举或构造及结果，验证点 2 写边界、端点、退化、重复或反例及结果。

#### Scenario: 跨关键检查保持步骤格式
- **WHEN** 多步推导主动暂停检查关键结论并收到结果后继续
- **THEN** 每步仍使用固定五字段及连续显示编号，工具请求和检查报告另行保存，不把报告拼成数学步骤或要求模型输出内部思考

#### Scenario: 验证先于最终答案生成
- **WHEN** 验证阶段已通过并完成最终答案生成
- **THEN** 程序仍将最终答案排在关键验证点之前，章节不缺失、不重复，不让模型重写完整四章节

#### Scenario: 暂停续写后的步骤合并
- **WHEN** 一个数学步骤跨越多轮生成及 Python 调用后完成
- **THEN** 详细解题步骤仅渲染一次该步骤，包含完整指定字段与真实计算依据，不泄露工具控制标签或重复编号；同一轮生成的其他步骤分别保存、显示和审计

#### Scenario: 多轮步骤的最终组装
- **WHEN** 多个步骤逐轮完成且整题验证通过
- **THEN** 系统按有效证明顺序组装已保存步骤，不在最后重新请求模型生成全部详细步骤，也不丢掉必要证明链；简单题允许最初一次推导请求完成多个步骤及候选

### Requirement: 最终答案类型与证明保留
系统 MUST 按 answer_mode 格式化：非 proof 的确定数值、集合、选项或表达式使用 `$\boxed{\cdots}$`，统计题保留所需字段，多问逐项完整回答；choice 最终只含选项字母，多个字母不带逗号；fill_blank 使用完整术语。非 choice、judgment、fill_blank、proof 优先数学公式、集合、关系、坐标方程或数值，不用含糊自然语言替代对象。proof 不强求框，最终总结完整命题、解集或构造，详细步骤保留完整证明，不能仅输出“命题成立”。

#### Scenario: 证明正文保留
- **WHEN** answer_mode=proof 且证明经过多轮推导
- **THEN** 最终答案总结被证明命题，详细步骤保留必要证明链，不被答案抽取或上下文精炼删掉

#### Scenario: 未完成例外
- **WHEN** 预算耗尽或验证未通过
- **THEN** 四章节保持存在，最终答案明确写未完成及缺口、不框猜测；关键验证点如实写失败或未执行，不伪造两个成功验证
