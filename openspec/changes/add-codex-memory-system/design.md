## Context

参见 [proposal.md](proposal.md)。仓库主体是 Python 推理代理，记忆系统以 Go 为核心实现；允许使用最小 Python 辅助层接入 `custom2_staged`，也允许使用 JavaScript 编写协议客户端、调试工具或集成测试。辅助语言不承担记忆决策和存储语义。

## Goals / Non-Goals

**Goals:**

- 以 Go 实现分层记忆、检索、安全策略、生命周期、持久化和协议服务。
- 通过稳定 JSONL 协议提供语言无关边界，保持无网络、可降级和可审计。
- 用小型 Python 适配层将 Go 服务接入现有代理，同时保持平台入口兼容。
- 允许 JavaScript 复用同一 JSONL 协议实现可选调试和集成工具，而不扩展核心语义。

**Non-Goals:**

- 不在 Python 或 JavaScript 中重复实现写入门禁、检索排序、生命周期或持久化。
- 不使用 CGo、FFI、Rust 或 C/C++ 实现核心能力。
- 不提供 HTTP 服务、远程数据库、向量数据库、用户画像或聊天历史。
- 不持久化原题、答案、原始响应、完整提示词、评测元数据、秘密或绝对路径。

## Decisions

### 1. 独立 Go 模块

在 `memory/` 下建立独立 `go.mod`。布局为 `cmd/memoryd` 可执行入口，以及 `internal/model`、`store`、`policy`、`retrieval`、`service`、`protocol` 包。核心实现与单元测试使用 Go，模块元数据使用 `go.mod` 和必要的 `go.sum`。独立进程方案避免 CGo 和 ABI 耦合，并允许 Python 仅通过标准流调用。

### 2. 三层记忆与权威顺序

逻辑层为 `working`、`episodic` 和 `experience`。前两层绑定请求作用域并在关闭时释放；经验层可选跨运行。权威顺序为“调用方当前约束 > 当前请求已验证证据 > 情节记忆 > 经验记忆”。经验只能作为建议，不能自行改变验证状态。

### 3. 版本化 JSONL 标准流协议

每行请求包含 `version`、`request_id`、`operation` 和 `payload`；响应包含相同标识、`ok`、`result` 或安全错误。首版操作为 `open_scope`、`remember`、`recall`、`invalidate`、`feedback`、`close_scope`、`health`。标准输出只写协议响应；诊断写标准错误且不包含正文。相比 HTTP，JSONL 不引入端口、认证和网络生命周期。

### 4. 结构化条目与确定性门禁

条目包含稳定 ID、模式版本、类型、作用域、规范化正文、内容哈希、来源类别、时间、置信度、验证状态、标签、效用、访问统计、过期时间和失效原因。ID 由作用域、类型和规范化内容的 SHA-256 派生。

跨运行写入依次执行类型 allowlist、长度限制、禁存内容扫描、题面/答案重合检测、数字与实体密度检查、验证状态、去重和容量判断。只接受 Go 中确定性模板产生的通用方法、风险和检查规则。

### 5. 标准库词法检索

检索使用 Unicode 文本规范化后的 token/字符 n-gram 重合，加类型、阶段、验证状态、效用和时效评分。先过滤后评分，以稳定 ID 解决并列，再应用 top-k、单条字节上限和总预算。首版不使用嵌入模型或第三方包。

### 6. 版本化 JSON 快照

持久层使用带 `schema_version`、`generation`、`updated_at` 和 `entries` 的 JSON 快照。写入采用同目录临时文件、`Sync` 和 `os.Rename` 原子替换；进程内使用 `sync.RWMutex`。首版为单写者，无法安全写入时降级只读。

加载设置文件大小和条目数上限；损坏、校验失败或未知版本快照被隔离，服务以空经验层继续工作，不自动迁移或覆盖原文件。

### 7. Go 核心配置与验证

配置只来自 Go 命令行参数和环境变量，默认启用题内记忆、禁用持久化写入。路径必须显式提供。测试使用 `testing`、`t.TempDir`、可注入时钟和表驱动用例；验证命令为 `go test ./...`、`go test -race ./...`、`go vet ./...`。

### 8. Python 薄适配与 staged 接入

Python 辅助层负责启动/关闭 `memoryd`、发送带请求 ID 的 JSONL、执行超时与响应模式校验，并把安全统计映射到现有 trace。它不解析或改写记忆条目语义，也不在 Go 进程失败时本地复制记忆逻辑。

`custom2_staged` 在策略规划前召回方法经验、求解/修复前召回风险经验、审计后写入题内记忆，并在返回前提交通过 Go 门禁的经验候选。功能由配置开关控制；Go 二进制缺失、超时、崩溃或协议错误时关闭当前记忆会话并沿原无记忆路径继续。

### 9. JavaScript 可选辅助工具

JavaScript 可实现 JSONL 协议客户端、交互式调试器、快照检查入口或端到端测试驱动。它必须只消费 Go 返回的结构化结果，不直接读写内部快照，不复制安全门禁或检索规则；不需要 JavaScript 能力时无需创建相关代码。

## Risks / Trade-offs

- [辅助语言可能复制核心逻辑] → Python/JavaScript 限定为进程、协议、上下文组装、调试和集成验证；所有策略决定由 Go 响应给出。
- [进程协议存在启动与序列化开销] → 采用常驻进程和流式多请求，限制消息大小。
- [经验可能污染后续请求] → 默认关闭持久化写入，执行确定性门禁并允许失效。
- [词法检索召回有限] → 优先无依赖与确定性，保留 Go scorer 接口。
- [多进程一致性有限] → 首版单写者；无法确认安全时只读降级。

## Migration Plan

1. 创建独立 Go 模块、领域模型和协议契约，先保持 Python 路径不变。
2. 完成内存存储、安全策略、检索和生命周期，并通过 Go 单元及竞态测试。
3. 完成 `memoryd` JSONL 服务和端到端协议测试。
4. 增加最小 Python 客户端并以默认关闭的配置接入 `custom2_staged`。
5. 最后加入默认关闭的快照持久化及故障降级。
6. 回滚时关闭 Python 记忆开关即可恢复原路径；Go 模块和快照不是代理启动必需项。
