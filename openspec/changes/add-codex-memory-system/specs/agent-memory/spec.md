## Purpose

该能力为推理代理提供有界、可审计且默认安全的记忆机制，使当前题目的可靠信息能够跨阶段复用，并允许经过验证和去题目化的经验在显式授权时跨运行复用，同时避免评测数据泄漏、错误经验污染和上下文失控。

## ADDED Requirements

### Requirement: Go 核心与辅助语言边界
记忆系统的领域模型、存储、检索、安全策略、生命周期、持久化和服务端 MUST 使用 Go 实现。系统 MAY 使用 Python 或 JavaScript 实现薄适配、Go 子进程管理、协议调用、调试工具和集成测试，但辅助层 MUST NOT 重复实现或绕过 Go 核心的写入门禁、排序、隔离、淘汰和持久化语义。

#### Scenario: 检查实现边界
- **WHEN** 审查本变更产生的 Go 核心及 Python/JavaScript 辅助代码
- **THEN** 所有记忆决策与存储语义均位于 Go 模块，辅助代码仅负责适配、进程生命周期、协议传输、调试工具和集成验证

#### Scenario: 独立验证 Go 核心
- **WHEN** 不启动 Python 运行时而构建和测试 Go 模块
- **THEN** 全部核心记忆行为仍可通过 Go 单元测试、竞态检测和协议测试验证

#### Scenario: Python 适配调用
- **WHEN** Python 代理启用记忆功能
- **THEN** 适配层通过版本化 JSONL 协议调用 Go 进程，且 Go 进程不可用时安全退回无记忆路径

#### Scenario: JavaScript 辅助调用
- **WHEN** JavaScript 客户端或调试工具调用记忆功能
- **THEN** 它通过相同版本化 JSONL 协议调用 Go 进程，且不会在本地重现 Go 核心策略

### Requirement: 独立进程协议
系统 SHALL 以独立 Go 可执行程序提供版本化 JSONL 标准输入/输出协议。每个请求和响应 MUST 为单行 JSON、包含协议版本和请求标识；协议错误 MUST 返回结构化错误且不得导致后续有效请求无法处理。

#### Scenario: 处理有效请求
- **WHEN** 客户端向标准输入写入一个受支持版本的有效 JSONL 请求
- **THEN** 系统在标准输出返回具有相同请求标识的单行 JSON 响应

#### Scenario: 处理无效请求
- **WHEN** 客户端发送畸形 JSON、未知操作或不受支持的协议版本
- **THEN** 系统返回不泄露内部数据的结构化错误，并可继续处理下一条有效请求

### Requirement: 分层且有作用域的记忆
系统 MUST 区分单次调用内的工作记忆、当前题内的情节记忆和可选的跨运行经验记忆。每个条目 MUST 包含稳定标识、类型、作用域、规范化内容、来源类别、创建时间、置信度、验证状态和版本；不同题目的题内记忆 MUST 相互隔离。

#### Scenario: 新题启动时隔离题内记忆
- **WHEN** 同一代理实例开始处理新的 `solve` 请求
- **THEN** 系统为新请求建立独立题内作用域，且前一题的原始事实、候选答案和失败细节不可被新题检索

#### Scenario: 条目可被审计
- **WHEN** 系统接受一个记忆条目
- **THEN** 条目具有完整的作用域、来源、验证状态和模式版本，且可通过稳定标识进行更新或失效

### Requirement: 默认安全的运行模式
系统 SHALL 默认启用当前题内记忆，但 MUST 默认禁用跨运行写入。未配置持久化后端、运行目录不可写或后端不可用时，系统 MUST 继续解题并退化为进程内记忆。

#### Scenario: 默认配置运行
- **WHEN** 调用方未提供任何记忆配置
- **THEN** 当前题内记忆可用、不会创建跨运行记忆文件，且平台入口和返回值契约保持不变

#### Scenario: 持久化后端失败
- **WHEN** 已配置的持久化后端在读取或写入时失败
- **THEN** 当前题求解继续执行，系统记录有界错误统计并使用可用的进程内记忆

### Requirement: 受控的记忆写入
系统 MUST 通过确定性的写入门禁决定条目是否可保存。跨运行记忆仅可包含经过验证、去题目化且可复用的方法、风险模式或检查规则；系统 MUST 拒绝保存原题文本、题目特有常数或实体、候选或最终答案、参考答案、原始模型响应、完整提示词、平台元数据、密钥和本地路径。

#### Scenario: 经验通过持久化门禁
- **WHEN** 一个已验证结论被抽象为不含题目特有信息的通用方法，且跨运行写入被显式启用
- **THEN** 系统可将其作为经验记忆保存，并记录抽象来源和验证依据的非敏感摘要

#### Scenario: 敏感或题目特有内容被拒绝
- **WHEN** 候选条目包含原题片段、答案、元数据、秘密或无法完成去题目化
- **THEN** 系统拒绝跨运行写入，且审计信息只包含拒绝原因代码而不包含被拒内容

### Requirement: 有界且确定性的检索
系统 SHALL 根据当前问题、阶段、记忆类型、验证状态、相关性、时效性和历史效用检索记忆。检索 MUST 支持类型过滤、数量上限和字符预算；相同输入与相同存储快照 MUST 产生稳定排序。

#### Scenario: 在预算内返回相关记忆
- **WHEN** 求解阶段请求与当前任务相关的记忆并给定条目数与字符预算
- **THEN** 系统仅返回符合类型和作用域的最高排序条目，且序列化结果不超过预算

#### Scenario: 排序分数相同
- **WHEN** 多个合格条目的排序分数相同
- **THEN** 系统使用稳定标识作为最终决胜条件并返回确定顺序

### Requirement: 当前证据优先和冲突隔离
记忆内容 MUST 被视为可撤销的辅助建议，不得覆盖原始题面、当前题内已验证事实或协议约束。系统检测到冲突时 MUST 排除或降级冲突记忆，并记录其失效或待复核状态。

#### Scenario: 经验与当前题事实冲突
- **WHEN** 检索到的经验与当前题面或已验证事实冲突
- **THEN** 系统不将该经验作为可信前提注入，并保留当前题证据的权威性

#### Scenario: 记忆不能独立证明答案
- **WHEN** 某候选答案仅由历史记忆支持而无当前题推导或验证
- **THEN** 系统不得因该记忆而将候选标记为已验证或完成最终门禁

### Requirement: 生命周期、去重与淘汰
系统 MUST 支持内容去重、效用反馈、失效、过期和容量淘汰。同一规范化内容在同一作用域内重复写入时 SHALL 合并证据和使用统计而非无限追加；超出容量时 SHALL 优先保留已验证、高效用且近期使用的条目。

#### Scenario: 重复经验写入
- **WHEN** 同一规范化经验被再次接受
- **THEN** 系统更新现有条目的统计与来源摘要，且不会创建语义重复记录

#### Scenario: 容量达到上限
- **WHEN** 新条目写入会超过条目数或总字符容量
- **THEN** 系统按确定性策略淘汰低优先级条目，并保证存储仍满足配置上限

### Requirement: 安全的持久化与并发行为
启用本地持久化时，系统 MUST 使用带模式版本的 JSON 安全格式、原子替换和进程内同步，且 MUST 将损坏或未知版本数据视为不可用。系统不得依赖持久化成功来完成当前题。

#### Scenario: 写入过程中发生中断
- **WHEN** 持久化写入在替换目标文件前失败
- **THEN** 原有有效快照保持可读，临时数据不会被当作有效记忆加载

#### Scenario: 加载损坏或未知版本快照
- **WHEN** 存储文件无法解析、校验失败或模式版本不受支持
- **THEN** 系统隔离该快照、使用空的跨运行记忆继续运行，并输出不含原始内容的诊断事件

### Requirement: 有界上下文注入
系统 MUST 按求解阶段将记忆渲染为明确标记的非权威上下文，并在注入前执行去重、截断和字符预算检查。记忆注入 MUST 为提示词保留题面、约束、当前任务和已验证证据所需空间。

#### Scenario: 上下文空间不足
- **WHEN** 可用提示词预算小于所有候选记忆的总长度
- **THEN** 系统按排序逐项选择或截断记忆，而不截断当前题的核心约束和已验证证据

#### Scenario: 没有合格记忆
- **WHEN** 检索结果为空或所有结果均被冲突/安全过滤器拒绝
- **THEN** 系统不注入空模板噪声，并按无记忆路径正常求解

### Requirement: 最小化可观测性
系统 SHALL 提供记忆检索、命中、写入接受/拒绝、淘汰、降级和耗时的有界统计。稳定 `trace` 与可选 `debug_trace` MUST 不包含跨运行记忆正文、原题副本、原始模型响应、秘密或持久化绝对路径。

#### Scenario: 记录一次检索
- **WHEN** 系统完成记忆检索
- **THEN** 审计事件仅包含作用域、候选数、命中数、预算、耗时、条目标识哈希和原因代码等安全字段

#### Scenario: 协议响应可序列化
- **WHEN** 记忆服务完成一次协议请求
- **THEN** 响应是单行合法 JSON，且诊断字段不会包含记忆正文、秘密或绝对路径

### Requirement: 可测试和可替换的边界
系统 SHALL 通过统一存储与检索契约支持内存后端和可选本地持久化后端，且核心行为测试 MUST 不依赖网络、真实模型调用、系统时钟抖动或未声明的全局状态。

#### Scenario: 使用内存后端执行确定性测试
- **WHEN** 测试注入固定时钟、固定条目和内存后端
- **THEN** 写入门禁、排序、预算、去重、失效与淘汰结果可重复验证

#### Scenario: 更换后端
- **WHEN** 一个后端实现满足相同存储契约
- **THEN** 上层运行时无需改变平台入口、记忆条目模式或检索语义即可使用该后端
