## Why

当前各运行时分别维护 `AgentState`、失败路线、候选草稿和策略检索结果，缺少统一的记忆模型、注入边界、淘汰策略与安全约束，导致上下文重复、跨阶段信息丢失且难以测试。需要建立一个默认安全、可审计、可降级的记忆系统，在不改变平台入口契约的前提下提升单题推理的一致性，并为经过净化的可复用经验提供可选持久化能力。

## What Changes

- 引入统一记忆分层：单次 `solve` 内的工作记忆、当前题内的情节记忆，以及显式启用的跨运行经验记忆。
- 定义记忆条目的结构化模式、来源、作用域、置信度、验证状态、有效期、容量成本与稳定标识。
- 定义写入门禁：只有经过验证、去题目化和敏感信息过滤的抽象经验才可进入跨运行持久层；原题、候选/参考答案、原始模型响应、评测元数据和秘密永不持久化。
- 定义检索、排序、上下文预算、去重、冲突处理、失效和淘汰规则，使记忆注入保持有界且不得覆盖当前题面与已验证状态。
- 提供可替换的存储接口与默认内存实现；可选本地持久化实现必须显式配置、原子写入、格式可迁移且损坏时安全降级。
- 记忆系统的核心领域逻辑、存储、检索、安全策略、生命周期和服务端以 Go 实现；允许使用少量 Python 或 JavaScript 完成代理适配、协议工具、进程管理和集成测试。
- 通过版本化 JSONL 标准输入/输出协议连接 Go 服务与 Python `custom2_staged`，保持核心记忆能力不依赖 Python 实现。
- 增加不依赖真实模型调用的模式、生命周期、安全、排序、预算、并发与降级测试，以及只暴露统计信息的审计事件。

## Capabilities

### New Capabilities

- `agent-memory`: 规定推理代理的分层记忆、受控写入、相关性检索、上下文注入、存储生命周期、安全隔离、可观测性与故障降级行为。

### Modified Capabilities

无。

## Impact

- 预计新增独立 `memory/` Go 模块，包括 `cmd/memoryd`、内部领域包、存储、检索、安全策略与 Go 测试。
- 预计在 `reasoning_agent/` 增加最小 Python 客户端适配，并修改 `custom2_staged` 的配置、提示组装和安全 trace；不改变平台公开入口契约。
- Go 核心仅使用标准库，不引入外部数据库或网络服务；Python/JavaScript 辅助层不复制核心策略，并优先使用现有依赖与标准能力。
- 记忆内容不进入稳定 `trace`；诊断数据只记录条目数量、命中数、淘汰原因和稳定哈希等有界统计。
